# Feature Tracker — App Design Specification v1

Production-grade visual + interaction spec for the main Feature Tracker application.
Generated by ChatGPT against the current stack, current design tokens, and the existing problems.
Implement verbatim — exact hex codes, class strings, copy, and token values are deliberate.

## 1. Brand & Voice

**Name:** Feature Tracker

**Tagline (current):** Track projects, features, and flows across environments.

**Refined tagline candidates (use one):**
- "Track, verify, ship — across every environment."
- "The calm control room for engineering teams."
- "From feature to verified flow."

**Design philosophy:**
- Calm, technical, and confident.
- A control room for engineers — not a marketing surface.
- The interface should make live verification feel observable and trustworthy.
- AI surfaces should feel integrated, not bolted on.
- Visual hierarchy communicates state. Decoration only when it earns its place.

**Voice rules:**
- Sound like a senior engineer writing for a senior engineer.
- Use precise verbs: verify, capture, navigate, inspect, transition, escalate.
- Never use vague copy: "Something went wrong", "No data", "Are you sure?".
- Errors explain what happened, why, and what the user can do next.
- Empty states always explain what is missing, why it matters, and what the user can do.
- Never anthropomorphize the AI assistant. It assists; it does not "think" or "feel".

**Anti-patterns (forbidden throughout the app):**
- Generic SaaS blue as the signature color.
- Pages made entirely of identical border + white cards.
- Single giant spinner for an entire page.
- Empty states that say "No data".
- Decorative animation that does not communicate state.
- Color-only communication (always pair color with icon + text).
- Stock illustrations of robots, cartoon people, or 3D objects.

- `h1`: `text-2xl font-semibold tracking-tight`
- `h2`: `text-xl font-semibold tracking-tight`
- `h3`: `text-lg font-semibold`

### 3.4 Weight usage

- 400 — body, helper
- 500 — emphasized body, lead
- 600 — headings, button text

## 4. Spacing / Radius / Shadow

### 4.1 Spacing

Use Tailwind defaults. Common internal rhythm:

- Inside cards: `p-5` (compact `p-4`, spacious `p-6`).
- Between sections: `space-y-8`.
- Between cards in a list: `space-y-3`.
- Sidebar item padding: `px-3 py-2`.

### 4.2 Radius

| Token | Value | Use |
|---|---|---|
| `rounded-md` | 6px | Small chips, checkboxes |
| `rounded-lg` | 8px | Inputs, buttons |
| `rounded-xl` | 12px | Cards, panels |
| `rounded-2xl` | 16px | Dialogs, hero surfaces |
| `rounded-full` | 9999px | Avatars, badges, pills, launcher |

Primary CTA may use `rounded-xl` instead of `rounded-lg`.

### 4.3 Shadow (Tailwind additions)

```js
boxShadow: {
  soft: "0 1px 2px 0 rgb(15 23 42 / 0.04)",
  card: "0 2px 8px -2px rgb(15 23 42 / 0.08)",
  "card-hover": "0 8px 24px -8px rgb(15 23 42 / 0.16)",
  elevated: "0 12px 32px -12px rgb(15 23 42 / 0.22)",
  dialog: "0 24px 64px -16px rgb(15 23 42 / 0.32)",
  ai: "0 12px 40px -12px rgb(99 102 241 / 0.28)",
}
```

| Shadow | Use |
|---|---|
| `soft` | Subtle elevation on flat surfaces |
| `card` | Default card |
| `card-hover` | Card hover lift |
| `elevated` | Popover, dropdown |
| `dialog` | Modal, sheet |
| `ai` | AI launcher + AI surfaces |

Cards transition between `shadow-card` and `shadow-card-hover` on hover.

## 11. Animations & Micro-interactions

### 11.1 General rule

Motion communicates state. It should not exist merely because animation is possible.

`opacity + translateY(4px)`, `160–180ms`. Do not use large page slides.

Enter `opacity 0 → 1` + `scale .98 → 1`, `180ms`.

`200ms`. Icon and label transition together. Do not independently animate every child.

### 11.6 Cards

### 11.7 Buttons

Hover: brightness / background change. Pressed: `scale-[0.98]`. Do not bounce.

Active progress ring has a subtle pulse. Timeline current item uses `animate-progress-pulse`. Avoid blinking status indicators.

### 11.9 AI launcher

Hover `translateY(-2px)` + shadow increase. Open `scale .98 → 1` + `opacity 0 → 1`.

## 14. Accessibility Checklist

### 14.1 Contrast

- Normal text: `4.5:1`
- Large text: `3:1`
- UI components: `3:1`

Primary indigo must be tested against its actual background. Do not use muted text for essential information.

### 14.2 Focus

All interactive elements must have visible focus:

```
focus-visible:outline-none
focus-visible:ring-2
focus-visible:ring-ring
focus-visible:ring-offset-2
```

### 14.3 Keyboard navigation

Required: `Tab · Shift+Tab · Enter · Space · Escape · Arrow keys where appropriate`.

Existing shortcut `b` toggles sidebar. Shortcut must not trigger while the user is typing inside `input`, `textarea`, `[contenteditable]`.

### 14.4 Sidebar

Use `<nav aria-label="Primary navigation">`. Current item: `aria-current="page"`.

### 14.5 Dialog

Radix Dialog provides required primitives. Ensure: title exists · description exists · focus trap works · Escape closes · focus returns to trigger.

### 14.6 Drawer

Same requirements as dialogs. Issue drawer: `aria-label="Issue details"` or proper `DialogTitle`.

### 14.7 Chat

Container: `<section aria-label="AI Assistant">`. Messages: `<div role="log" aria-live="polite">`. Do not make every message an alert. Only important status transitions should be announced. Example: `Verification completed. Two issues were found.`

### 14.8 Chat input

- `aria-label="Ask the AI assistant"`
- Send `aria-label="Send message"`
- Attach `aria-label="Attach file"`
- Collapse `aria-label="Collapse AI assistant"`

### 14.9 Verification status

Do not rely only on green/red/amber. Always pair color with icon + text. Example: `✓ Verified`, not merely `●`.

### 14.10 Reduced motion

Respect `prefers-reduced-motion`.

## Final Visual Rules

These rules govern the engineer implementing this specification.

**Rule 1 — Indigo is identity.**
Use `#6366F1` as the signature Feature Tracker color.

**Rule 2 — Cyan means environment.**
Use `#06B6D4` for environment-specific visual language.

**Rule 3 — Violet means AI.**
Use `#8B5CF6` alongside indigo for AI surfaces.

**Rule 4 — Red means actual failure.**
Do not use red decoratively.

**Rule 5 — Cards need hierarchy.**
Avoid a page of identical border + white background cards. Use background / surface / card / elevated / dialog layers.

**Rule 6 — The Issue Tracker is the product centerpiece.**
It should visually communicate: Target → Run → Live verification → Evidence → Issues → Action.

**Rule 7 — The AI Assistant is always available.**
Every authenticated page must retain the fixed bottom-right AI launcher. The assistant should feel integrated into Feature Tracker rather than bolted on.

**Rule 8 — Verification should feel alive.**
When Playwright is running, users should see progress, current page, current action, timeline, console activity, network failures, completion state. Never hide browser activity behind a spinner.

**Rule 9 — Empty states explain what to do next.**
Never ship `No data.`. Use: what is missing · why it matters · what the user can do.

**Rule 10 — Motion communicates state.**
Use animation for opening, closing, loading, progress, state changes. Not for decoration.

**Rule 11 — Preserve the current architecture.**
Do NOT introduce Tailwind 4, CSS modules, another component library, another state library, another router, another headless UI system.

Keep:
- React 18
- TypeScript
- Vite
- Tailwind 3
- shadcn/ui
- Radix
- TanStack Query
- Zustand
- React Router
- Lucide
- Sonner
- react-hook-form
- Zod
- Blocks SDK
- Blocks IAM
- Blocks Data

**Rule 12 — Preserve existing primitive APIs.**
Existing shadcn components should remain compatible with current call sites. Visual changes should happen primarily through variants, tokens, className defaults, CSS variables, and shared component styles. Do not force a broad rewrite merely to change visual styling.
